# Nutrition signup for Bark clients

- Public entry: `/nutrition` (rewrites to `nutrition.html`). This is the link JT sends Bark clients. Existing clients can sign in on the same page.
- The primary CTA uses the existing live Stripe Payment Link with `client_reference_id=nutrition` and `utm_source=jt_nutrition`. The price remains GBP 12.99 per month after the existing 30-day trial; no Stripe product, price, tax or subscription settings are changed. Signup alerts continue to validate the same Payment Link.
- The checkout return verifies the live completed subscription and expected price server-side, then routes nutrition checkouts to nutrition account setup. The account email must match checkout and be verified before `/api/claim-membership` connects it. Pending checkout IDs survive email confirmation in user metadata, but never grant access by themselves. A failed claim preserves the pending ID and tells the client not to pay again.
- New accounts use the existing Supabase email confirmation flow through `/performance-hub-free-profile.html`. `service_focus: nutrition` routes them to `/nutrition-programme.html` on confirmation and subsequent Hub login. This editable preference only selects a page; all server authorization and paid membership checks remain unchanged.
- The existing new-user trigger creates the client profile. Football onboarding is not required for nutrition. Opening the nutrition workspace saves the nutrition service preference for client accounts; staff retain their normal Hub. Existing nutrition clients also return to nutrition from the main Hub, dashboard and AI Coach bookmarks.
- The nutrition workspace reuses the existing personal programme API, questionnaire, private coach drafts and publication checks. Its dedicated navigation is Today, Week, Shop, Progress, AI Coach and Support. It includes recipe visuals, meal completion, ingredient quantities, available source-checked shopping estimates, daily check-ins and coach notes. JT reviews drafts through the existing Hub programme screen before sharing.
- JT AI Coach requires a verified account, active/trialing membership and explicit AI consent, with the existing 20-question daily allowance. Nutrition mode uses only the signed-in client's own nutrition intake and latest published plan under RLS. It does not require a football profile, expose drafts, change plans or send messages to JT. Unknown/under-18 ages receive family-oriented guidance without weight-loss or calorie targets. Health notes, names and emails are excluded from the structured AI context.
- Support links to a real email draft to JT, the saved questionnaire and progress check-ins. Billing returns nutrition clients to their nutrition workspace. The separate nutrition manifest starts at `/nutrition-programme.html`.
- Creating only an account takes no payment and activates no subscription. Existing standalone programme quote/intake access is preserved; AI Coach membership checks remain enforced on the server.
- Password recovery uses the existing reset page in update mode. Email delivery still depends on the existing Supabase mail and redirect configuration.

Validation: `tests/nutrition-signup.test.mjs` and `tests/nutrition-experience.test.mjs` cover signup/confirmation routing, claim failures, live checkout validation, errors, login, recovery, AI consent/membership and own published-plan context. The personal-programme suite checks privacy, coach publication and consent. A synthetic local browser fixture exercised desktop/mobile landing, checkout return, shared/empty plans, questionnaire, shopping, check-ins, AI response rendering and Support. No real client signup emails, payments or AI requests are used. ## Individual client prices

JT can open `/nutrition-pricing.html` directly or use **Nutrition prices** from the owner Hub toolbar. Separate programme quotes appear under Support and are explicitly separate from the GBP 12.99 Hub membership. Enter the client’s sign-up email, a GBP amount, one-off/monthly basis and a description. Clients see only an active quote whose email exactly matches their verified Supabase account email. Email aliases are not merged. An existing quote can be edited or hidden; changing its email requires a new quote.

The editor saves quotes only. It does not take payments, start subscriptions, change existing Stripe charges or grant paid membership. Custom programme payment remains arranged with JT; the standard Hub subscription is collected through the existing Stripe link above.

The API is under `/api/hub-session-plans?programme=nutrition-pricing`. Owner authorization is checked on the server, without trusting browser role metadata. Direct browser reads/writes to `hub_nutrition_quotes` are revoked and RLS is enabled. The client lookup uses the server-verified email, not a supplied email parameter. Updates use a revision predicate to reject stale edits. No real client prices were created while developing this feature.

Validation: `node --test tests/nutrition-pricing.test.mjs tests/nutrition-signup.test.mjs tests/personal-programmes.test.mjs` passes 32 tests. `tests/nutrition-pricing-rls.sql` passes against the deployed schema and rolls back its synthetic row. The editor, update and client display were also exercised in a local browser fixture.
